Inclusive Access: team testing guide

How to get the latest version, run it, and test everything: audio in six languages, keyboard, screen readers, zoom, colours, offline, and the partner integrations.

Repository: github.com/newal-dev/new-track1 · Branch: samuel · 15 November 2026 · About 60–90 minutes of testing

Fastest way: use section 1 to set up by hand, or copy the prompt in section 2 into an AI coding agent (Claude Code, Cursor, Copilot agent, Codex) and let it set everything up and run the automated tests for you. Then do the hands-on tests in sections 3–8 yourself: they need a person.

1. Get the code and run it

You need Git, Docker Desktop (started), and Chrome or Edge. The audio clips (528 files, about 16 MB) are inside the repository, so cloning downloads them; there is nothing extra to fetch.

First time

git clone https://github.com/newal-dev/new-track1.git
cd new-track1
git checkout samuel
docker compose up --build

Already cloned before

cd new-track1
git fetch origin
git checkout samuel
git pull origin samuel
docker compose up --build

Wait for Plugin server on http://localhost:3000, then open http://localhost:8080. To stop: Ctrl+C, then docker compose down.

Without Docker: install Node.js 20 or newer, run npm ci, then npm start in one terminal and npm run demo in a second.

"port is already allocated" or the page looks like a different project? Another app is using port 3000 or 8080. Run docker ps, stop the other containers with docker stop <name>, and start again. The plug-in only works on these two ports.

Check the audio arrived

In the project folder, public/audio/ must contain six folders, each with 88 .mp3 files:

en  am  om  ti  so  sid

Quick check in a browser: http://localhost:3000/audio/am/welcome.mp3 should play.

Automated tests (one person is enough)

npm ci
npm test                         # expect: 95 pass (unit, voice, API)
npx playwright install chromium
npm run test:a11y                # expect: 27 passed (browser + axe accessibility)
npm run contrast                 # expect: 75 of 75 pairs pass

Stop Docker first (docker compose down) before npm run test:a11y: it starts its own servers on ports 3000 and 8080.

3. Audio test (20 min, one person per language)

Laptop, Chrome or Edge, volume up. Native speakers are the most valuable here.

  1. Open http://localhost:8080. The first page asks "Which language would you like to use?" and is read aloud after you press any key or tap.
  2. Choose your language: English, አማርኛ, Afaan Oromoo, ትግርኛ, Soomaali or Sidaamu Afoo.
  3. "Would you like this page to be read aloud?" is spoken. Press Yes.
  4. Go through every page of Join the programme, Apply for a job and For employers (top menu). On each page check:
    • you hear it, in your language (silence or the wrong language is a bug);
    • the spoken words match the screen;
    • pronunciation is understandable (write down words that sound wrong);
    • after reading you hear "Speak now", a beep, and a Listening banner appears.
  5. Language page: the English voice names only English; then each language invites you in its own voice and by its own name. Say your language's name in your own words (for example "አማርኛ"): it should be chosen. If it is not understood, you hear "Please say the name of your language again" in English and Amharic, then a second beep.
  6. Tab test: press Tab and Shift+Tab. Each choice (radio choices too) is read as number, name and "selected" or "not selected". The consent boxes on the review page are read in your language.
  7. Review page: it is read in your language: each answer with its number and question, then the consent sentence and "Do you want to submit your answers?". A typed name is read by an English voice if your device has none for your language.
  8. Press Escape: all sound stops at once.
  9. Native speakers: also check the written text. All non-English text is a draft.
Known, do not report: job titles and typed names are read by the device voice, or by an English voice when the device has none for your language (Ge'ez is then spelled in Latin letters), so they can sound foreign. The support and adjustment pages are long (40–60 seconds) because they read every choice. Sidaamu Afoo is a rough first draft waiting for native review; two Sidama clips (closing date hint, "did not understand") drop the letter v. Please do report wrong Sidama words: that review is exactly what is needed.

4. Voice answers (10 min, Chrome or Edge)

  1. Choose a language, press Yes to read aloud, and allow the microphone.
  2. After the beep, answer with a number ("two"), a choice name, or a command: Next, Back, Skip, Read aloud, Stop.
  3. On the phone or email question, say the number: "zero nine one one…" (also in your language). It is filled in and read back digit by digit. Say "Next".
  4. On the last page say "Yes" to submit. If you chose support needs, it asks whether to share them too: say Yes or No.
  5. Write down what was misunderstood. Afaan Oromoo, Tigrinya and Sidama usually have no browser speech recognition: typing is expected there.

5. Keyboard only (10 min)

Do not touch the mouse. Use Tab, Shift+Tab, arrow keys, Space, Enter, Escape.

  • Complete all three forms.
  • The keyboard help strip at the top (Tab, Shift+Tab, Space/Enter, Esc) is in the language you chose.
  • On "How would you like to show who you are?", Tab visits every choice; Enter chooses it (no error); Enter again goes on.
  • On a checkbox page, Enter ticks a box; Enter on a ticked box goes on; Space unticks.
  • The focus is always clearly visible.
  • Next with an empty answer shows an error and moves the focus to the field.
  • On the review page, "Yes, submit" without ticking the consent box shows an error and sends nothing.

6. Screen readers (15 min each, the most important test)

Do the sign-up, ideally with our co-designer, without helping. Note where they hesitate and whether they finish.

  • NVDA + Chrome (Windows): free from nvaccess.org. Every question, hint, choice and error should be read.
  • TalkBack (Android): phone on the same Wi-Fi as the laptop; open http://<laptop-IP>:8080 (find the IP with ipconfig). The microphone does not work over plain http on a phone: type instead.
  • Record each session with docs/manual-test-script.md: device, versions, finished yes/no, time, problems. These results go into section 1.2 of docs/WCAG-2.2-AA-Report.md and are required to pass the judging gate.
